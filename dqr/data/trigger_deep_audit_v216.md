# v216 作成済みデッキ 発動トリガー詳細検証

基準: `js/app.js` 内の `SOLO_PRESET_DECK_DEFS` 4デッキ。  
対象トリガー: 速攻 / 召喚時 / 死亡時 / 攻撃時 / におうだち / パワフルバッジ / 占い / れんけい。  
ユーザー裁定反映: レッドプレデターは敵ユニット限定。れんけいはテンション3で発動し、テンションは消費しない。

## v216で実修正したもの

### レッドプレデター
- v215: `target:'enemyAny'` だったため敵リーダーも対象候補になり得た。
- v216: `beginPendingUnitTargetV202({kind:'damageBySourceAttack', target:'enemyUnit', canLeader:false, forceChoiceModal:true})` に変更。
- 期待挙動: 召喚時、自身の攻撃力を特技使用回数分上げた後、敵ユニット1体だけを対象選択し、そのユニットへ自身の攻撃力ぶんダメージ。

### 占い使用回数カウント
- v215: `handleCardPlayedEvent` 側でも `hasFortuneEffect(card)` を見て `totalFortuneEffectsUsed` を加算していた。
- 問題: `applyTabasaFortuneCardV187` / `resolveFortuneV187` 側でも占い回数を加算するため、バルーンコール・かみかぜ・太陽のタロットなどで二重カウントになり得る。
- v216: `cardPlayed` 側の占い加算を削除し、実際に占いが解決される側でだけ加算する方針へ修正。
- 期待挙動: タロットフォーチュン等の「対戦中に自分が使った占いカードの回数」参照が1枚使用につき+1になる。

## 共通対象選択モーダル検証

`unitTargetRefsForAnyTargetV208` / `openEffectTargetChoiceModalV208` 系で対象選択はかなり共通化されている。

- `unitAny`: 味方・敵の通常ユニット。建物/ダンジョンは除外。
- `enemyUnit`: 敵の通常ユニット。敵リーダーは含まない。
- `enemyAny`: 敵ユニット + 敵リーダー。
- `friendlyUnit`: 味方の通常ユニット。
- `friendlyDungeon`: 味方ダンジョン専用。
- ステルス中の敵ユニットは通常の効果対象から除外。
- におうだちは攻撃対象だけを制限し、効果対象は制限しない。
- 対象候補が1体だけでもモーダルを出す設計になっている。

## れんけい検証

### 共通発動条件
- `applyRenkeiIfActive` で `game.player.tension >= 3` を確認。
- テンションを減らす処理はこの関数内に存在しない。
- したがって「テンション3なら発動、消費しない」という裁定と一致。
- 勇者イレブンLv2の一心同体例外のみ、テンション3未満でも発動可能な分岐がある。

## 死亡時検証

### 共通死亡処理
- `resolveDeaths` がHP0以下を検出。
- 死亡時は `emitBattleEvent('unitDeath')` → 盤面から除去 → `applyDeathrattle` の順。
- `vanished` が true の場合は死亡時を発動しない。
- `extraDeathText` により、さくせん等で後から得た死亡時も発動可能。
- v214コメント通り、後付け死亡時では元カード全文を誤って読ませないガードがある。

### 作成済みデッキ内死亡時カード

| カード | 実装状況 | 挙動 |
|---|---|---|
| ラプソーン | 専用/汎用混在 | ランダムな敵ユニットに「死亡時: 相手の場にラプソーン」を付与。付与先死亡時の復活位置は要確認。 |
| ベホイミスライム | 実装あり | 死亡時GET(1)。コインを手札に加える。 |
| 怪獣プスゴン | 専用実装あり | 死亡時、正面のランダムな敵空きマスにイチゴ爆弾。 |
| プチマージ | シンクロ後死亡時 | ヒーローLv2以上で死亡時に魔法使い特技をランダムに手札へ。 |
| メルビン | 専用実装あり | 死亡時、ホットストーンをデッキ上から3番目へ。 |

### 死亡時要確認
- ラプソーンの復活先: 現状は「効果を付与した側の空きマス」へ出す系統。公式挙動が「同じマス優先」「ランダム空きマス」なら要調整。
- 怪獣プスゴン死亡時の「正面のランダムな敵の空きマス」: 現状は同じ行の敵前列/後列の空きからランダム。裁定確認候補。
- メルビンの「上から3番目」は `idx = Math.min(2, deck.length)` で処理。デッキ枚数0〜1のときは末尾相当になる。

## パワフルバッジ検証

### 共通処理
- 召喚時に `flags.powerBadge` があれば `registerPowerfulBadgeV157`。
- `player.powerfulBadges` / `enemy.powerfulBadges` に永続保存。
- 盤面補正系は `applyPowerfulBadges` で再計算。
- 手札コスト低下系は `getPowerfulBadgeCostDeltaV157`。
- 「ユニットカードを使う度」「ターン終了時」系は専用trigger配列で処理。
- 解除は公式DB文面にある特定カードだけ実装対象でOK。

## におうだち/速攻検証

### におうだち
- `hasTauntOnSideV173` / `canAttackTargetUnitV173` / `canAttackLeaderV173` で攻撃対象制限。
- ねらい撃ち持ちはにおうだちを突破可能。
- ステルス中のにおうだちは攻撃強制対象から除外。
- 効果対象はにおうだちでは縛らない。

### 速攻
- `applySummonKeywords` で `flags.haste` または `flags.firstStrike` があれば `canAttack=true` / `summoningSickness=false`。
- パワフルバッジやシンクロ等で後から速攻が付く場合も、該当処理で攻撃可能化しているものが多い。
