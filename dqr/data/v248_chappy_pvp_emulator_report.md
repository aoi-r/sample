# v248 あらくれチャッピー対人モード検査

## 概要
2つの独立したChromiumクライアントを起動し、Firebase action logに相当する送受信をテストブリッジで中継して、対人モードの reducer / mirror 処理を検査した。実IPを2つ用意した本番Firebase接続ではなく、同一コード上のaction payloadを相手クライアントへ流す方式。

- 結果: 14 passed / 0 failed
- 検査対象: あらくれチャッピー（召喚時：ユニット1体に2ダメージ）

## 確認済み
- OK: two clients booted with test hook
- OK: チャッピー: 非ターン側は召喚できない
- OK: チャッピー: 対象モーダルはユニットのみ/リーダーなし
- OK: チャッピー: 敵ユニットへ2ダメージが双方で1回だけ反映
- OK: チャッピー: 味方ユニットも対象にできる
- OK: チャッピー: 味方対象ダメージも相手画面へ正しくミラー
- OK: チャッピー: 対象死亡時も双方で盤面から消える
- OK: チャッピー: 場に出すでは召喚時モーダル/ダメージは出ない

## 重要な確認点
- 非ターン側は召喚不可。
- 召喚時にユニットのみ対象モーダルが出る。リーダーは対象に出ない。
- 敵ユニットを対象にした2ダメージは、自分側・相手側の両画面で1回分だけ反映。
- 味方ユニットを対象にした2ダメージも、相手画面では敵側盤面へ正しくミラーされる。
- 対象が死亡した場合、unitDeath actionで双方の盤面から消える。
- 効果で「場に出す」場合、召喚時モーダル・ダメージは発動しない。

## 実装メモ
- v248では通常動作に影響しないテスト用hook `window.__DQR_TEST__` を拡張。
- Firebaseに接続できない環境でもPvP action reducerを確認できるよう、`window.__DQR_TEST_BRIDGE__` 有効時だけ action outbox を使う。
- `makeActionPayload` はFirebase未読込環境でもテストできるよう `serverTimestamp()` 未定義時に `Date.now()` を使う。
